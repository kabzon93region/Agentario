# v0.14.73 — Исправление метрик компакции

## Проблема

В статусе компакции отображались некорректные цифры токенов. Три разных метода подсчёта давали три разных результата:

- `createTokenEstimator()` (сериализованные сообщения с кэпами): ~7,885 токенов
- `estimateTokens(JSON.stringify(...))` (сырой JSON без кэпов): 39,440 токенов
- `JSON.stringify(ctx.messages).length` (символы, включая system prompt + tools): 120,918

Пользователь видел `39,440→1,096 токенов (сохранено 38,344, 97%)` — цифра не соответствовала ни модели (26k total), ни реальным токенам чата (~15.8k).

## Что исправлено

### Единый метод подсчёта
- `sdk-compaction-coordinator.ts`: заменён `estimateTokens(JSON.stringify(...))` на `createTokenEstimator("compaction")` — единый estimator с кэпами thinking (2k) и tool_result (2k)
- Теперь цифры отражают реальные токены чата, а не сырой JSON

### Per-chunk статистика
- Wrap-up чанки: `Wrap-up чанк 1/3: ~5,200 ток. на входе` → `Wrap-up чанк 1/3 готов: ~380 ток. на выходе`
- Стандартные чанки: `Чанк 1/3: ~5,200 ток. на входе` → `Чанк 1/3 готов: ~380 ток. на выходе`

### Терминология
- "сохранено" → "освобождено" в статусе сжатия

### Lab API
- `/api/compact` теперь возвращает `contextTokens` (оценка токенов) alongside `contextChars`

## Ожидаемый результат

```
Сжатие выполнено: 18→3 сообщ., ~15,800→~1,100 токенов (освобождено ~14,700, 93%)
```

Вместо:
```
Сжатие выполнено: 18→3 сообщ., 39,440→1,096 токенов (сохранено 38,344, 97%)
```
